# Исправления бэкенда — что изменилось

28.10.2026. Исправлены пункты бэкенда из `ОТЧЁТ-ПРОВЕРКИ.md`. Новых зависимостей нет, схема базы не менялась (только запросы).

## Что сделать на сервере

1. **Сменить пароль root** на сервере. Он лежал открытым текстом в `deploy/deploy.ps1` и `deploy/deploy-simple.ps1` — из скриптов убран, но остаётся в истории git. Если репозиторий публичный, считайте пароль утёкшим.
2. Вход по SSH-ключу: `ssh-copy-id root@сервер` один раз, затем отключить вход по паролю (`PasswordAuthentication no` в `/etc/ssh/sshd_config`).
3. Запустить `deploy/deploy.sh` заново — сервис будет работать от пользователя `pressa`, а не от root (скрипт сам создаст пользователя и выставит права).
4. В `/opt/pressa/.env` добавить `SESSION_COOKIE_SECURE=1` (после настройки https) и проверить, что задан `SECRET_KEY`.
5. Перезапустить: `sudo systemctl restart pressa`.

Необязательные настройки в `.env`: `TASK_WORKERS` (одновременных генераций на весь сервис, по умолчанию 4), `TASK_ACTIVE_LIMIT` (незавершённых задач на пользователя, 2), `TASK_HOURLY_LIMIT` (задач на пользователя в час, 60), `DISPLAY_TZ_OFFSET` (часовой пояс для дат, 3 — Москва).

## Мелочи

- Вместо 500 — понятные ответы: `days=abc`, `post_id=abc`, `/survey/submit` с не-объектом, битым JSON или числовым `title`, импорт JSON с `"title": 123`, пароль длиннее 72 байт (при регистрации — сообщение, при входе — «Неверный email или пароль»).
- Неизвестный `task_type` — 400, задача не создаётся.
- Статус или удаление несуществующего пункта плана — «Пункт плана не найден».
- Даты показываются по Москве в формате «28.10.2026 13:49» (фильтр `|local_dt`).
- Активный медиа-образ при одинаковом времени создания — последний по id.
- При ошибке генерации картинки шаблоны остаются на странице.
- После регистрации — переход сразу в анкету медиа-образа.
- Ссылки на презентацию со страницы `/presentation-tz` работают: `/presentation.pdf`, `/presentation.pptx` (файлы из корня проекта).
- Тексты: «TenChat», «Инструкция для ИИ».
